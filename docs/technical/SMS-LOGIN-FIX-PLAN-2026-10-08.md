# 短信登录/注册故障核查及待批准修复方案

日期：2026-10-08。状态：用户已批准，修复、本地验收和生产部署完成。GitHub 发布分支 `codex/sms-login-recovery-2026-10-08`。实施结果见 `docs/releases/sms-login-fix-2026-10-08.md`。以下保留批准前的核查依据与方案。

## 已确认根因

1. 前后端发送状态契约不一致。`src/app/api/user/route.ts` 在供应商传输异常时保留预先落库的验证码，返回 HTTP 202、success=true、deliveryState=unknown，允许收到短信的用户继续验证。`src/components/LoginModal.tsx` 的 goToVerify 却在 unknown 分支提前 return，未执行 setPhoneStep('verify')。验证码输入框只在 verify 步骤渲染，因此出现“提示可以输入，但无输入框”，同时获取按钮被倒计时锁定。resendCode 也把 unknown 当作错误呈现。
2. 恢复入口缺失。验证码页返回手机号页后，倒计时内无法再次进入验证码页；关闭弹窗会清空手机号、验证码、步骤和倒计时，但不会清除服务端限流，再打开可能遇到 429，仍然没有继续输入入口。
3. 错误归因过度合并。fetch 异常、JSON 解析异常和登录 Session 同步失败被统一显示为网络/验证失败。发送请求未收到响应也不意味着短信没有发出，目前该路径同样无法进入验证码页。

“失败后整个弹窗自动消失”尚未确认：发送/验证错误分支本身没有调用关闭。已发现的关闭入口包括遮罩点击、Escape、关闭按钮及登录同步成功。需要浏览器复现确认是否误触或组件生命周期变化，不能把此现象直接归因于上述 return。

## 核查证据与边界

- 提取当前 goToVerify 实际函数体，注入模拟响应执行：正常 success 响应结果 step=verify；unknown 响应结果 step=input、countdown=60，错误文案仍提示直接输入。此为函数级复现，不是完整浏览器端到端验收。
- 执行 `npx vitest run __tests__/lib/sms-client.test.ts`，6 项通过。这些测试不覆盖 LoginModal 状态转换。
- 旧发布文档 v10.100.0 已描述后端超时保留验证码策略，但当前前端未完成对应交互。
- 本轮未发送真实短信、未取得本次生产故障请求日志，也未确认线上部署与当前工作区完全一致。因此供应商此次是否超时、是否还有其他生产错误，尚需按请求号核查。
- 工作区已有其他未提交改动，包括 user API 的配置错误提示改动；修复时保留这些改动。

## 拟实施方案

1. 统一发送结果分类：已受理、状态未确认、明确拒绝。success+unknown 进入验证码页，用非阻断提示说明状态未确认，保留输入、粘贴及验证能力，并保持重发冷却。首次发送与重发共用同一处理逻辑。
2. 浏览器网络中断或非 JSON 网关响应归为结果未确认，提供继续输入路径，不自动补发短信；明确参数错误、限流、数据库错误、供应商拒绝保留准确提示，不伪装为已发送。
3. 为已尝试发送的同一手机号增加“已收到验证码，继续输入”入口，支持返回和重新打开后的恢复；修改手机号时隔离旧状态。用截止时间计算冷却，防止关闭弹窗、后台停留导致计时失真。不持久化验证码或密码。
4. 登录/注册错误留在当前步骤，保留可安全重试的数据；区分验证码错误、服务异常、Session 同步失败。仅在确认登录状态成功后自动关闭。请求期间防止遮罩误触退出，并处理旧请求响应及自动验证定时器，避免关闭/切换手机号后旧结果污染新流程。
5. 保持服务端验证码校验、有效期、尝试次数和限流约束；统一必要的结构化状态与请求号，记录不含敏感信息的排障事件。生产问题按请求号关联发送审计和运行日志，避免无证据调整短信供应商配置。

## 验收要求

- 200 进入输入页；202 unknown 同样可输入，且不自动重发。
- 网络中断但短信已到，可继续输入并完成真实服务端校验。
- 429/503 展示准确错误；同手机号已有验证码时仍有继续输入入口。
- 返回、关闭重开、切换手机号、请求中误触、晚到响应均不会丢失正确流程或串号。
- 错码保留页面并显示剩余次数；正确码覆盖老用户登录、新用户注册、已有账号补设密码。
- Session 同步失败保留恢复入口，确认成功后才关闭。
- 桌面及手机浏览器验证键盘输入、粘贴、短信自动填充和后台切回；补充组件/浏览器行为回归测试及 API 契约测试。
- 上线验收使用获准测试号码，记录请求号和发送—收到—输入—登录完整结果，不记录明文验证码。

批准后实施上述修复和本地验证；部署按实际发布授权执行。
