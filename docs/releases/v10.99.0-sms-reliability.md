# v10.99.0 — 登录验证码可靠性修复

发布日期：2026-07-14

## 根因

生产日志确认首个验证码请求由 Vercel 香港函数访问阿里云 DYPNS 时发生连续连接超时，接口先返回 500。旧实现随后只回滚本机内存，没有释放 Supabase 中已消费的短信限流额度，因此同一用户的重试被继续返回 429“请60秒后再试”。

## 修复

- 使用阿里云公开的 RPC HMAC-SHA1 签名协议，通过运行平台原生 `fetch` 发送 DYPNS 请求，绕开旧 SDK 的 `httpx` 传输层。
- 将账号验证码、密码重置和短信就绪探针隔离到实测可达的 Vercel 东京区域，避开香港及新加坡区域到 DYPNS 的稳定连接超时；下载与生成区域保持不变。
- 发送请求不做模糊网络超时自动重试，避免服务商已收到请求时重复下发短信。
- 新增数据库 `release_rate_limit` 原子释放函数；供应商失败和验证码落库失败都会等待限流额度释放完成。
- 重写 `consume_rate_limit` 为同 key 事务锁保护，拒绝请求不再增加计数。
- 发布迁移时清除旧实现遗留的受污染限流窗口。

## 安全边界

- 手机号每 60 秒一次、手机号小时额度、IP 每分钟及小时额度保持不变。
- 阿里云返回真实频控错误时仍向客户端返回 429 和服务商等待时间。
- 日志不记录验证码、完整手机号、AccessKey Secret 或完整供应商请求 URL。

## 验证结果

- 全量商业预检通过：43 个测试文件，219 项通过、1 项跳过；70 个生产路由构建成功。
- RPC 签名参数按 ASCII 字节序排序，并由测试重新计算签名验证；供应商模糊网络超时不会自动重复下发。
- 生产数据库限流验证通过：首次允许、第二次拒绝、释放成功、再次允许。
- 东京探测 HTTP 200、461ms；生产连续三次短信就绪检查均通过，耗时分别为 451ms、205ms、200ms。
- 账号与就绪接口的生产执行区域均确认为 `hnd1`；当前部署未再出现旧 `httpx` 或 ConnectTimeout 日志。
- 为避免向未授权号码发送短信，自动验收不触发真实下发；最终短信到达由业务手机号验收。
