# 短信登录/注册输入恢复修复

日期：2026-10-08。状态：本地修复和验收完成，尚未部署。

## 问题与结果

原先后端返回 HTTP 202、success=true、deliveryState=unknown 时，前端提前返回，仍停在手机号页并锁定 60 秒，导致收到短信也没有验证码输入框。现在未确认状态进入验证码页，用非阻断文案提示用户查看短信；网络断开、超时和非 JSON 网关响应同样保留输入路径，不自动重发。明确拒绝仍显示真实错误。

返回手机号页或关闭重开后可继续输入。同手机号的冷却按截止时间恢复；切换号码隔离旧验证码与状态。信息只保留在当前组件内存，关闭清空验证码和密码，不写 localStorage/sessionStorage。整页刷新或跨路由重新挂载不保证恢复内存状态；再次遇到 429 时仍提供已收到验证码的输入入口。

遮罩和 Escape 不再中断进行中的请求；新增显式关闭按钮，允许主动退出。关闭/卸载会取消本地请求与自动验证定时器，忽略晚到响应。取消客户端请求不能撤销已经提交的短信或服务端登录操作。

验证码、注册和密码登录共用请求生命周期和防重复提交逻辑。短信请求最长等待 35 秒，登录 Session 同步最多等待 15 秒。收到成功账号结果但 Session 同步失败时，保留单独重试同步按钮，避免重复注册或发送短信。确认 Session 已登录且用户 ID 匹配后才更新登录用户并关闭弹窗。

另修复 320px 窄屏验证码格子溢出，输入区随可用宽度缩放，弹窗可纵向滚动。

## 修改范围

- `src/components/LoginModal.tsx`：状态恢复、单一路径发送、错误处理、防误关、请求取消、验证码自动提交清理及窄屏布局。
- `src/lib/login-request.ts`：共享有界请求、发送结果分类和等待时间解析。
- `src/lib/auth-context.tsx`：可取消、有超时的登录状态同步；由弹窗在确认成功后负责关闭。
- 未改变后端验证码校验、有效期、短信限流或供应商配置，也未覆盖工作区原有改动。
