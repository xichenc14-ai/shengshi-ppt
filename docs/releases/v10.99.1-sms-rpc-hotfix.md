# v10.99.1 — 验证码真实 RPC 链路修复

发布日期：2026-07-14

## 复现证据

用户在生产环境 13:36 发起真实验证码请求，Vercel 日志确认 `SendSmsVerifyCode`
等待 10 秒后被客户端超时中止并返回 HTTP 500。v10.99.0 的 HEAD 就绪探针同期正常，
证明该探针只覆盖 CDN 入口，无法代表真实签名 RPC 请求可用。

## 修复

- DYPNS RPC 从空 body POST 切换为官方 RPC 支持的 GET 请求，并按 GET 重新计算 HMAC-SHA1 签名。
- 默认请求超时由 10 秒调整为 20 秒，仍不对结果不明确的发送请求自动重试。
- 就绪检查改为调用不发送短信的 `CheckSmsVerifyCode` 签名请求；网络、签名、AccessKey 或产品权限异常均判定未就绪。
- 保留数据库限流预留/失败释放机制，真实发送失败不会污染下一次重试。

## 验收要求

- 生产签名 RPC 就绪检查成功。
- 生产真实 `send_code` 返回 HTTP 200，阿里云返回 `Code=OK`。
- 真实手机号收到验证码并可完成登录后方可关闭问题。
